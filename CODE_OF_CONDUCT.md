# Code of Conduct

NeuroNest is an open, actively developed project, and this document exists to keep collaboration on it respectful, constructive, and focused on building good software together. It applies to anyone participating in NeuroNest's project spaces — contributors, maintainers, and community members alike.

---

## Our Standards

Examples of behavior that contribute to a positive environment include:

- Communicating respectfully, even in disagreement.
- Giving and receiving constructive criticism gracefully.
- Conducting technical disagreements in good faith, backed by reasoning and evidence.
- Welcoming newcomers and helping them get oriented.
- Being open to different viewpoints, backgrounds, and levels of experience.
- Focusing criticism on ideas, code, designs, and decisions — not on the people behind them.
- Taking responsibility for mistakes and learning from them.
- Helping maintain a productive, focused engineering environment for everyone involved.

Disagreement about architecture, implementation choices, AI system design, performance trade-offs, or product direction is a normal and healthy part of building software. It is not, by itself, a violation of this Code of Conduct.

---

## Unacceptable Behavior

The following behavior is not acceptable in NeuroNest's project spaces:

- Harassment of any kind.
- Discrimination based on personal characteristics.
- Personal attacks or insults directed at individuals.
- Threats or intimidation.
- Trolling or deliberately disruptive behavior intended to derail collaboration.
- Deliberate humiliation or belittling of others.
- Sexual harassment or unwelcome sexual attention.
- Hate speech.
- Doxxing or exposing someone's private information without consent.
- Sharing credentials, secrets, or private user data in project spaces.
- Malicious behavior directed at project infrastructure (e.g. repositories, CI, issue tracker).
- Retaliation against anyone who raises a legitimate concern in good faith.

To be clear: disagreeing with someone's code, architecture proposal, or technical opinion is not unacceptable behavior. Personal attacks, harassment, and bad-faith conduct are.

---

## Scope

This Code of Conduct applies to interactions within NeuroNest's project spaces, including:

- GitHub issues
- Pull requests
- Code reviews
- GitHub discussions
- Documentation contributions
- Any other project-related communication conducted through this repository

---

## Enforcement

NeuroNest does not currently have a formally designated community moderation team. Within project-controlled spaces, maintainers are responsible for addressing reported violations of this Code of Conduct.

Depending on the severity and nature of an incident, maintainers may take proportionate action, which could include:

- Requesting a change in behavior
- Removing or editing inappropriate content
- Closing the relevant issue, pull request, or discussion
- Restricting a person's participation in project spaces
- Temporarily or permanently removing someone's ability to participate, in serious or repeated cases

There is no guaranteed timeline for enforcement actions; response depends on maintainer availability and the severity of the situation.

---

## Reporting

If you experience or witness behavior that violates this Code of Conduct, please report it privately to the project's maintainers using an appropriate private GitHub mechanism where available (for example, a private message to a maintainer), rather than posting about it publicly.

Please do not include sensitive personal information about yourself or others in a public report.

**This process is separate from security vulnerability reporting.** If you've found a security vulnerability, do not report it here — follow the process described in [`SECURITY.md`](./SECURITY.md) instead, and do not publicly disclose exploit details through GitHub issues.

---

## Enforcement Guidelines

When addressing reported violations, maintainers will aim to be:

- **Consistent** — applying similar standards to similar situations.
- **Proportionate** — matching the response to the severity of the behavior.
- **Good-faith** — assuming good faith where reasonably possible, while still protecting the community from genuine harm.
- **Evidence-based** — decisions will be grounded in the information available.
- **Community-focused** — the goal of enforcement is to protect the ability of the community to collaborate productively, not to punish for its own sake.

Maintainers will avoid unnecessary public disclosure of private information gathered during the handling of a report.
